### What are the main reasons why you enjoy using GraphQL?

* Avoiding Over-fetching — Keep API responses smaller by specifying exactly the data you need.
* Introspection & API Documentation — Create self-documenting APIs that improve the developer experience.
* Tooling & Ecosystem — The different tools, services, and libraries that use GraphQL.
* Type-checking — Enforcing and validating types for every object in the API.
* Combining Different APIs — Being able to combine together different API schemas.
* Aggregating Requests — Only ever have to make a single request from the client.
* Community — The people who are active in the GraphQL space.
* Fragment Colocation — Being able to colocate a component's data requirements next to it.

### What are your main pain points when using GraphQL?

* Performance — Performance issues such as the n+1 problem.
* API Versioning — Handling deprecated fields and other versioning concerns.
* Client-side Caching — Caching data on the client, updating the cache, optimistic UI, etc.
* Combining Different Schemas — Being able to combine together different API schemas.
* Error Handling — Returning errors and managing them on the client.
* File Upload — Being able to upload files through your GraphQL API.
* Security — Security issues such as infinitely nested queries.
* Testing — Testing your GraphQL API.
